# どこいく

日付・自宅からの距離・価格でホテルの空室を比較検索するWebサービスのMVPです。
楽天トラベル空室検索APIを利用しています。

## セットアップ

このプロジェクトはご自身のPC(ローカル環境)で以下の手順を実行してください。
Node.js 18以上がインストールされている必要があります。

```bash
# 1. 依存パッケージをインストール
npm install

# 2. 環境変数ファイルを作成
cp .env.example .env.local
```

`.env.local` を開き、楽天ウェブサービスの「アプリ情報の確認」ページで取得した
値を入力してください。

```
RAKUTEN_APPLICATION_ID=（あなたのアプリケーションID）
RAKUTEN_AFFILIATE_ID=（あなたのアフィリエイトID）
```

```bash
# 3. 開発サーバーを起動
npm run dev
```

ブラウザで http://localhost:3000 を開くと画面が表示されます。

## 移動範囲(指定なし/距離/地方)の仕組みについて

楽天トラベル空室検索APIのエリアコード検索(`largeClassCode`/`middleClassCode`)は、
実際には市区町村レベルの`smallClassCode`まで指定しないとエラーになる仕様でした。
そのため、都道府県単体のコード検索はできません。

代わりに、**動作実績のある緯度経度検索(`searchRadius`、最大3km)を、
都道府県の代表地点(県庁所在地)ごとに繰り返す**方式を採用しています。

- `lib/prefectures.ts`: 47都道府県の代表座標と、伝統的な地方区分(東北/関東/東海/近畿など)
- `lib/distanceBands.ts`: 「小旅行(〜250km)/遠出(250km〜)」の距離帯判定と、
  範囲未指定時のデフォルト候補(自宅から80km以上離れたエリア)
- `app/api/hotels/route.ts`: `mode=none|band|region` を切り替えて、
  対象となる都道府県の代表地点を絞り込み、それぞれに検索をかけて統合

**制約と今後の改善余地**:
- 都道府県の代表地点(県庁所在地)周辺3kmのみのサンプリング検索のため、
  同じ都道府県内でも代表地点から離れた場所のホテルは拾えません。
  将来的には都道府県内に複数の検索地点を持たせる、またはGetAreaClass APIで
  取得した市区町村コードを使って`smallClassCode`まで指定した検索に
  置き換えることで、精度を上げられます。
- 1回の検索で複数地点にAPIリクエストを送るため、該当地点が多い場合は
  応答が遅くなったり、楽天APIのレート制限(429エラー)に引っかかる可能性が
  あります。現在は`MAX_AREAS_PER_SEARCH`(8件)・同時実行数3件に制限して
  いますが、必要に応じて調整してください。


## 人数指定について

大人・子供(小学生)・幼児の人数を指定できます。楽天APIは子供を
「小学生高学年/低学年」、幼児を「食事・布団の有無」で細かく分けていますが、
MVPでは以下のように簡略化しています。

- 子供(小学生) → `lowClassNum` に集約(高学年/低学年の区別なし)
- 幼児 → `infantWithBNum`(布団のみ、添い寝が多い一般的なケース)を使用
- 部屋数 → 現状は`roomNum=1`固定(将来的にUIで選べるようにする余地あり)

より細かい区分(食事あり/なし等)が必要になったら、
`lib/rakuten.ts`の`requestVacantHotels`内のパラメータを調整してください。

価格表示は「〜」を付けて、指定人数条件での最安プランの目安であることが
伝わるようにしています(`hotelMinCharge`は複数プランの中の最安値であり、
必ずしも予約可能な確定価格ではありません)。

## 追加機能(突発的な旅行向けの改善)

- **現在地から住所を自動入力**: 「📍現在地を使う」ボタンで、ブラウザの位置情報 →
  無料の逆ジオコーディング(Nominatim/OpenStreetMap)経由で住所欄を自動入力
  (`app/api/reverse-geocode/route.ts`)。Nominatimの利用ポリシー上、
  User-Agentの設定と過度な連続リクエストを避ける配慮をしています。
- **エリアごとのグルーピング表示**: 検索結果を都道府県ごとにグループ化して表示
  (`components/HotelList.tsx`)。グループの並び順は、そのエリア内の最安値が
  結果全体の中でどれだけ早く出てくるかに連動しています。
- **「おまかせで1件選ぶ」ボタン**: 検索結果からランダムに1件選び、
  ハイライト表示してスクロールします。行き先に迷ったときの後押し用。
- **絞り込み条件の追加**: 温泉宿のみ/禁煙ルームのみ(`squeezeCondition`)、
  上限予算(`maxCharge`)を指定できるようになりました。
- **検索中の進捗表示**: 本検索(`/api/hotels`)より先に、軽量なエリア判定のみの
  エンドポイント(`/api/areas`)を呼び出し、「検索中: 東京都 / 神奈川県 / …」を
  待ち時間中に表示するようにしました。ジオコーディングを2回行う分の
  オーバーヘッドはありますが、無料APIなのでコスト影響はありません。

## ホテルカードのリンク先について

ホテルカードのクリック先は、施設トップページ(`hotelInformationUrl`)ではなく
**プラン一覧ページ(`planListUrl`)** にしています。これは楽天API側が、
検索時に指定したチェックイン・チェックアウト日や人数条件を踏まえて
生成しているURLのため、クリック後もそのまま同条件のプラン一覧が
表示される想定です。`planListUrl`が空の場合のみ`hotelInformationUrl`に
フォールバックします。

## プランURLへの日付・人数の反映について

実際に試したところ、楽天APIが返す`planListUrl`には検索条件(日付・人数)が
含まれておらず、「日付指定なし」のページが開いてしまう問題がありました。

そのため、`lib/rakuten.ts`の`buildPlanUrl`関数で、楽天トラベルの検索フォームが
解釈するクエリパラメータ(`f_nen1`/`f_tuki1`/`f_hi1`などの年月日、`f_otona_su`の
大人数、`f_heya_su`の部屋数)をURLに追加しています。これらのパラメータ名は、
複数の実例URLから確認できたものです。

**注意**: 子供(小学生)・幼児の内訳を表す`f_s1`/`f_s2`/`f_y1`〜`f_y4`は、
公式ドキュメントが見当たらず、観測されたURL例からの推測で
`f_s2`(子供)・`f_y3`(幼児)としています。もし子供・幼児を指定した検索で
人数が正しく反映されない場合は、教えてください。パラメータの対応関係を
見直します。

## SEOにおける根本的な課題(要検討)

現在のトップページ(`app/page.tsx`)は`"use client"`で、検索結果はボタンを押した後に
クライアント側でAPIを叩いて表示される仕組みです。そのため、**検索エンジンが
最初にページを読み込んだ時点では、実際のホテル名や価格などの情報が一切存在しません**。

アフィリエイト収益はSEO経由の流入が生命線になるため、今後は以下のような
「あらかじめサーバー側で検索結果を埋め込んだ、クロール可能な入口ページ」を
別途用意することを推奨します。

- 例: `/areas/tokyo` のような都道府県別ページを Server Component で実装し、
  ページ読み込み時点でサーバー側が楽天APIを呼び出し、結果をHTMLに含めた状態で返す
- 各ページに、その地域・日付に関する説明文(H1・H2見出し、本文)を含める
- 内部リンク(都道府県間の相互リンクなど)を充実させる

このあたりは、既存のトップページ(検索フォーム)とは別に新しいページ群を
追加する、比較的大きめの実装になります。

## SEO用の都道府県別ページ(クロール可能な入口ページ)

`app/areas/[code]/page.tsx` を追加しました。これはサーバー側(Server
Component)で直近の週末の空室検索をあらかじめ実行し、結果をHTMLに
埋め込んだ状態でレスポンスするページです。検索エンジンのクローラーが
最初に読み込んだ時点で、実際のホテル名・価格が含まれています。

- URL例: `/areas/tokyo`(東京都)、`/areas/osaka`(大阪府)
- 都道府県コードは`lib/prefectures.ts`の`middleClassCode`と対応
- 47都道府県ぶんをビルド時に一括生成すると、デプロイのたびに楽天APIへ
  47回リクエストが飛んでしまうため、`generateStaticParams`は使わず、
  初回アクセス時に生成 → 1時間キャッシュ(ISR、`revalidate = 3600`)
  という方式にしています
- `app/sitemap.ts`に全都道府県ページを追加し、`components/Footer.tsx`
  (全ページ共通)に主要5都道府県への内部リンクを追加して、
  クローラーが実際にページを辿れるようにしています
- 各ページ下部には「他の都道府県から探す」として、残り46都道府県への
  リンクも設置しています(内部リンクの強化、回遊性の向上)

**今後の拡張余地**:
- ページ内の文章(紹介文)を都道府県ごとに個別化すると、より重複コンテンツ
  と判定されにくくなります(現状はテンプレート文言に都道府県名を差し込む形)
- トップページの検索フォームに、URLの`prefill`パラメータを読み取って
  「地方で選ぶ」モードを自動選択する機能を追加すると、都道府県ページの
  CTAボタン(「自分の日程で〇〇を検索する」)からの導線がより滑らかになります
  (現状はトップページに遷移するだけで、自動選択はしていません)

## 都道府県ページの紹介文を個別化

`lib/prefectures.ts`の各都道府県データに`catchphrase`(短い特徴フレーズ、
例: 北海道→「雄大な自然と海鮮グルメ」)を追加しました。また、その都道府県が
属する地方(東北・関東など)を逆引きする`regionKeyForPrefecture`関数も追加。

`app/areas/[code]/page.tsx`の紹介文・メタデータ(title/description)は、
これらの情報と近隣都道府県名を組み合わせて生成しているため、都道府県ごとに
文章の内容が実質的に異なります(単純な名前の差し込みだけではありません)。

## トップページの検索フォームで地方を自動選択

都道府県ページの「自分の日程で〇〇を検索する」ボタンから遷移した場合、
トップページの検索フォームが自動的に「地方で選ぶ」モードになり、
該当都道府県が属する地方(例: 東京都→関東)があらかじめ選択された
状態になるようにしました。

- `app/page.tsx`: URLの`prefill`パラメータ(都道府県コード)を読み取り、
  対応する地方を`regionKeyForPrefecture`で解決してフォームに渡す
  (`useSearchParams`を使うため、コンポーネントを`Suspense`でラップしています)
- `components/SearchForm.tsx`: `initialMode`・`initialRegion`という
  任意のpropsを受け取れるようにし、渡された場合はその値を初期状態にする
